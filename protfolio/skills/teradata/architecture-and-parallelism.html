Architecture and parallelism

Understand how Teradata parses a request and distributes work across processing components and AMPs.

ComponentsQuery examplePractice

01 / System model

Coordinate centrally, process in parallel.

Parsing Engine (PE)

Receives SQL requests, parses syntax, checks authorization, consults metadata, and creates an execution plan.

BYNET

Provides high-speed communication between system components, including the coordination and movement of work or data.

AMPs

Access Module Processors manage assigned rows and execute parallel steps such as scans, joins, and aggregations.

Parallel steps

When data is distributed well, many AMPs can work at once. Redistribution or skew can make one step wait for a small number of busy AMPs.

02 / Query example

Read the plan before guessing.

EXPLAIN reports planned access and processing steps. Use it to identify whether a query uses an index, scans a table, redistributes rows, or builds intermediate results.

EXPLAIN
SELECT customer_id, SUM(order_total)
FROM sales.orders
WHERE order_date >= DATE '2025-01-01'
GROUP BY customer_id;
Think through: Is the filter selective? Does the PI help access the rows? Are rows redistributed for the aggregation? Is the work balanced across AMPs?

03 / Practice

Interview checks.

What happens after a user submits a SQL request?

The Parsing Engine parses and validates the request, checks access, and generates a plan. The system coordinates steps across AMPs, which process their assigned rows in parallel; results are then returned to the requester.

Why can a parallel query still run slowly?

Work may be unevenly distributed, data may need redistribution, the plan may scan too much data, or a step may create large intermediate results. Use EXPLAIN and runtime evidence to find the limiting step.

What role does BYNET play?

BYNET provides communication between system components. It supports coordination and data movement required by distributed query steps.
