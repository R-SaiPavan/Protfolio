02 / Core notes

Concepts to explain clearly.

Parallel architecture

The Parsing Engine coordinates SQL; BYNET communicates between components; AMPs own and process assigned data in parallel.

Primary index

The PI controls row distribution and influences access. It is not automatically a business primary key; UPI and NUPI have different uniqueness behavior.

Skew and spool

Uneven distribution can make a few AMPs bottlenecks. Large intermediate results, skew, and poor plans can drive spool use.

Statistics and EXPLAIN

Statistics inform optimizer estimates. Use EXPLAIN to inspect planned access and joins, then validate against measured workload behavior.

03 / Interview practice

Questions and answer frameworks.

What do the Parsing Engine, BYNET, and AMPs do?

The Parsing Engine parses SQL and coordinates its execution plan. BYNET carries communication among system components. AMPs own portions of the data and perform parallel processing for their assigned rows.

How is a primary index different from a primary key?

A Teradata PI controls row distribution and can support access paths. A primary key is a logical integrity constraint. A PI does not necessarily enforce uniqueness; UPI does, while NUPI permits duplicates.

How would you investigate data skew?

Review row distribution, PI choice, and EXPLAIN output. Check if frequent values create hot AMPs or if joins redistribute large inputs. Consider a more even distribution strategy that still supports the workload.

Why do statistics matter to the optimizer?

Statistics improve estimates of row counts and value distributions, influencing join order and access methods. Collect stats on workload-relevant columns and validate with EXPLAIN and measured results.

What can cause a spool-space error?

Large intermediate results, poor join plans, skew, or unexpectedly high row counts can consume spool. Inspect EXPLAIN and step behavior, validate join conditions, and reduce unnecessary intermediate data.

How would you make an ETL load restartable?

Track source batches and load states, validate row counts and keys, and make target updates repeat-safe. Separate landing from publishing so a failed transformation can rerun without duplicating accepted records.
