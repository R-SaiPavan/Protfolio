02 / Core notes

Keep transformations modular and testable.

Models and refs

A model is a SQL select saved in the project. ref() creates a dependency and resolves the relation for the active target.

Sources

Sources name raw relations, support lineage, and can define freshness checks for upstream data.

Tests

Built-in tests validate properties such as uniqueness, non-null values, accepted values, and relationships. Add singular tests for domain rules.

Incremental models

Incremental models process new or changed data after the initial build. Define a unique key, filter strategy, and a safe full-refresh or backfill plan.

03 / Interview practice

Questions and answer frameworks.

What does ref() do?

ref() points to another dbt model, creates a dependency in the DAG, and resolves the correct relation for the current target environment.

How do generic and singular tests differ?

Generic tests are reusable parameterized checks such as unique or not_null. Singular tests are custom SQL queries written for a specific business rule; failing rows are returned by the query.

When should you use an incremental model?

Use one when rebuilding the full dataset is costly and new or changed records can be identified reliably. Define unique-key and update behavior, and test late-arriving data and full refreshes.

How do you keep dev and production data separate?

Use targets and environment-specific configuration, build in isolated schemas, promote reviewed code, and run production jobs with explicit permissions and validated artifacts.
