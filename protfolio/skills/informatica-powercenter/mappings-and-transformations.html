Mappings and transformations

Build a clear source-to-target data flow, understand row behavior, and choose transformations that match the requirement.

Mapping flowPatternsPractice

01 / Mapping flow

Make the row path understandable.

Sources and targets

Confirm definitions, datatypes, keys, and expected row grain before designing transformation logic.

Ports and links

Trace input and output ports through the pipeline. Check datatype compatibility and reject unexpected conversions.

Active vs passive

Active transformations may change row counts or row relationships; passive transformations generally pass rows through without changing their count.

Connected vs unconnected

Connected transformations sit in the data flow. Unconnected transformations are called explicitly, often as a lookup or reusable expression function.

02 / Example

Latest-record mapping pattern.

For a customer status feed, sort or rank records by customer key and update timestamp, keep the latest row, then route valid rows to the target and invalid rows to a reject path.

Validate input

Check required keys, timestamps, and status values; capture invalid records with enough context to correct them.

Deduplicate

Use a deterministic ordering and tie-breaker so reruns select the same source row.

Apply changes

Map the selected values to the target and define whether the load inserts, updates, or uses a separate merge step.

Reconcile

Compare source, accepted, rejected, and target counts for the batch.

03 / Practice

Interview checks.

How do you decide whether a transformation should be active or passive?

Start from its row semantics. If it filters, aggregates, or otherwise changes row count or relationships, it is active. Consider downstream behavior and performance when ordering transformations.

How would you handle invalid source rows?

Define validation rules, route rejected rows to a controlled path, capture error context, and report accepted and rejected counts. Avoid silently dropping records.

What do you check when mapping output differs from expectations?

Verify source definitions and grain, trace ports and datatypes, review transformation conditions and caches, inspect session logs, and reconcile counts at key points in the flow.
