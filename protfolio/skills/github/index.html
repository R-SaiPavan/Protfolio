02 / Core notes

Make changes reviewable and recoverable.

Working tree and index

The working tree contains current files; the staging index defines what goes into the next commit.

Commits

A commit records a snapshot and parent history. Small, focused commits make review and rollback easier.

Pull requests

PRs provide a place to compare changes, discuss them, run checks, and record approval before merging.

Automation permissions

Workflows should request only the token permissions they need. Store secrets in protected settings and avoid printing them in logs.

03 / Interview practice

Questions and answer frameworks.

What is the difference between git fetch and git pull?

Fetch downloads remote references without integrating them into the current branch. Pull fetches and then integrates, usually by merge or rebase depending on configuration.

When would you choose merge over rebase?

Merge preserves branch topology and creates a merge commit when needed. Rebase replays commits onto a new base for a linear history; avoid rewriting shared commits without coordination.

What makes a pull request easy to review?

Keep it focused, explain the problem and approach, include tests or evidence, call out risks, and respond to feedback. Let automated checks complete before requesting approval.

How should a workflow handle secrets?

Use repository or environment secrets, scope token permissions narrowly, protect sensitive environments, and avoid exposing secret values in logs or artifacts.
