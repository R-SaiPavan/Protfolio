SQL roadmap / 01

Query foundations

Write clear SELECT statements, filter correctly, handle NULL values, and make result ordering explicit.

ConceptsExamplesPractice

01 / Concepts

Be precise about the rows you want.

SELECT and projection

Select only needed columns. Explicit projections clarify the data contract and can reduce unnecessary data transfer.

Filtering and NULL

Use IS NULL and IS NOT NULL. Comparisons with NULL produce unknown, so use explicit null handling in filters and expressions.

CASE expressions

Use CASE to express conditional categories or derived values. Include an ELSE branch when a default is meaningful.

Ordering

Rows are not guaranteed to appear in a stable order without ORDER BY. Include a deterministic tie-breaker when selecting top rows.

02 / Example

Filter, derive, and order.

SELECT order_id,
       customer_id,
       CASE WHEN order_total >= 500 THEN 'large'
            ELSE 'standard'
       END AS order_band
FROM sales.orders
WHERE order_date >= DATE '2025-01-01'
  AND customer_id IS NOT NULL
ORDER BY order_date DESC, order_id;
Dialect note: date literals, boolean expressions, and limit syntax vary by database. Verify syntax for the engine you are using.

03 / Practice

Interview checks.

Why should you avoid SELECT * in production transformations?

It can read and expose unnecessary columns, make downstream schemas fragile, and obscure the intended output contract. Use explicit columns for clarity and controlled schema changes.

Why does column = NULL not find null rows?

NULL represents unknown, so ordinary equality comparison does not evaluate to true. Use IS NULL or IS NOT NULL.

When is ORDER BY required?

When the output order matters, such as presentation or deterministic top-N selection. Without it, row order is not guaranteed.
