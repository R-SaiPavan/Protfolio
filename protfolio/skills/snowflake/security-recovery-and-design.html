Security, recovery, and design

Practice explaining access control, protection of sensitive data, recovery boundaries, and workload design using clear operational examples.

Access controlRecoveryPractice

01 / Access design

Start with least privilege.

Role-based access control

Grant object privileges to roles, then grant roles to users or higher-level roles. Separate duties and use clear role ownership.

Masking policies

Conditionally transform sensitive column values based on the active role or context. Example: show a full email address to an approved support role and a masked value to other roles.

Row access policies

Filter which rows a query can return. Example: restrict users to records for regions they are authorized to view.

Shares and integrations

For governed data exchange, expose approved data through secure sharing patterns and tightly scoped cloud integrations rather than distributing credentials.

02 / Recovery and reliability

Know which recovery window applies.

Time Travel

Use the configured retention window to query historical data, clone an earlier state, or recover dropped objects. Retention limits depend on object type, edition, and configuration.

Fail-safe

A separate Snowflake-managed recovery period after Time Travel. It is not intended as a routine self-service restore mechanism; contact Snowflake Support when Fail-safe recovery is required.

Transient and temporary data

Choose table types intentionally. Transient tables trade away Fail-safe protection; temporary tables are scoped to a session. Match retention and recovery needs to the data.

Operational design

Combine least privilege, audit history, quality checks, failure alerts, and a tested replay plan. Document who owns recovery decisions and how downstream consumers are reconciled.

UNDROP TABLE analytics.customer_snapshot;
Example: if a table is accidentally dropped but remains within its Time Travel retention period, an authorized role may restore it with UNDROP TABLE. Confirm the recovered object and downstream data before resuming dependent jobs.

03 / Practice

Interview checks.

How do roles inherit access in Snowflake?

Privileges are assigned to roles. Roles can be granted to other roles to build inheritance, and users receive roles. The active role context determines which granted privileges are available in a session.

How is a masking policy different from a row access policy?

A masking policy changes the value returned for a column; a row access policy filters which rows are visible. Both should be tested with representative roles and governed under least-privilege access.

How would you recover a dropped table?

First establish whether the object remains within its Time Travel retention window, then use the appropriate recovery operation such as UNDROP TABLE. Fail-safe is a separate Snowflake-managed process, not an alternative query interface.
