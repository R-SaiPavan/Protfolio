02 / Core notes

Concepts to explain clearly.

Repository and Integration Service

The repository stores metadata such as mappings and workflows. The Integration Service executes configured workflows and sessions.

Mapping and workflow

A mapping defines source-to-target data flow and transformations. A workflow orchestrates sessions, tasks, dependencies, and recovery behavior.

Transformation behavior

Know whether a transformation is active or passive, connected or unconnected, and how it affects row counts, ordering, or caching.

Session and parameter files

Sessions bind mappings to runtime connections and options. Parameters externalize values that vary by environment or run.

03 / Interview practice

Questions and answer frameworks.

What is the difference between a mapping and a workflow?

A mapping describes the data transformation path from source to target. A workflow orchestrates execution, including sessions, dependencies, decision logic, and recovery paths.

How do connected and unconnected transformations differ?

A connected transformation participates in the mapping pipeline and receives rows through ports. An unconnected transformation is invoked explicitly, often through an expression, and returns a value to its caller.

How would you troubleshoot a session failure?

Start with session and workflow logs, identify the failing transformation or connection, inspect rejected rows and error codes, then verify source data and runtime configuration before rerunning safely.

How do you make a workflow restartable?

Define dependency and recovery behavior, isolate completed work, use parameters or control tables to track batches, and ensure rerunning a failed step does not duplicate target data.
