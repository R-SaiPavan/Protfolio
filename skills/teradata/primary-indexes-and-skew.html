Primary indexes and skew

Learn how the Primary Index affects row distribution and access, and how uneven distribution can become a performance bottleneck.

Index choicesSQL examplesPractice

01 / Data distribution

Choose for the workload and data.

Primary Index

The PI determines how rows are hashed and distributed among AMPs, and can provide an efficient path for matching values.

UPI vs NUPI

A Unique PI enforces uniqueness for its indexed value. A Non-Unique PI permits repeated values. Neither should be chosen without understanding source keys and data distribution.

Secondary indexes

Secondary indexes can support alternate access patterns, with additional maintenance and storage cost. Check the supported index type and workload before adding one.

Skew

Skew occurs when rows or processing are unevenly distributed across AMPs. Low-cardinality or heavily repeated PI values are common warning signs.

02 / SQL examples

Check cardinality and duplicates.

SELECT customer_id, COUNT(*) AS row_count
FROM staging.orders
GROUP BY customer_id
ORDER BY row_count DESC;

A possible table definition. Choose the PI from measured cardinality, skew, and common access patterns.

CREATE MULTISET TABLE mart.orders (
  order_id BIGINT,
  customer_id BIGINT,
  order_date DATE,
  order_total DECIMAL(12,2)
)
PRIMARY INDEX (customer_id);
Example decision: if most queries join by customer but a few customers contain a disproportionate share of rows, compare candidate PI distributions and workload benefits before committing to the design.

03 / Practice

Interview checks.

Does a Primary Index always enforce uniqueness?

No. A NUPI allows duplicate PI values. A UPI enforces uniqueness for its indexed value. A PI is primarily a distribution and access design choice, not automatically the same as a logical primary key.

How would you diagnose AMP skew?

Inspect row counts or workload by AMP, review the PI values and their frequency, and check EXPLAIN for redistribution and join steps. Compare candidate distribution keys against real query patterns.

What tradeoffs come with a secondary index?

It can speed selected access patterns, but adds storage and maintenance during writes. Confirm the workload benefit through measurement and account for the extra upkeep.
