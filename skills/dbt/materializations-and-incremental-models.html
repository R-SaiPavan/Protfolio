Materializations and incremental models

Choose how a model is built, then design incremental logic that handles updates, late data, and safe reprocessing.

MaterializationsIncremental examplePractice

01 / Build strategies

Choose by usage and workload.

View

Stores query logic and computes results when queried. Useful for lightweight transformations or data that should always reflect upstream state.

Table

Builds a persisted relation on a run. Useful when repeated query cost or downstream usage justifies rebuilding and storing the result.

Incremental

Processes a subset of new or changed records after the initial build. Requires reliable change detection and a defined update strategy.

Ephemeral

Compiles model logic into dependent SQL rather than creating a persisted relation. Use selectively because large expansions can make generated SQL harder to manage.

02 / Incremental example

Filter new records deliberately.

{{ config(
    materialized='incremental',
    unique_key='order_id'
) }}

SELECT order_id, customer_id, updated_at
FROM {{ ref('stg_orders') }}
{% if is_incremental() %}
  WHERE updated_at > (SELECT MAX(updated_at) FROM {{ this }})
{% endif %}
Design checks: define how updates to existing keys are merged, how late-arriving records are captured, and when a full refresh or targeted backfill is needed. Exact behavior depends on adapter and configuration.

03 / Practice

Interview checks.

What should you define before making a model incremental?

Choose a change filter, unique key or merge strategy, behavior for updates and deletes, late-arriving data handling, and a way to recover with full refresh or backfill.

When would you choose a table instead of a view?

Choose based on query cost, freshness, storage, rebuild cost, and downstream usage. A table can reduce repeated computation; a view can avoid duplicated storage and remain current.

How would you validate an incremental change?

Compare a full-refresh result with the incremental result on representative data, including updates, duplicates, late records, and empty batches.
