dbt roadmap / 04

Deployment and documentation

Promote tested transformations through controlled environments and publish enough metadata for others to trust and use the data.

EnvironmentsWorkflowPractice

01 / Environments and artifacts

Separate development from production.

Targets

Use profile targets or managed environment configuration to select warehouse, schema, and credentials per environment.

Jobs

Run scheduled production builds with explicit selections, concurrency expectations, and alerting for failures or stale data.

Artifacts

Run results and manifests capture execution and project state. Use them to support observability, lineage, and state-aware workflows.

Documentation

Describe models, columns, sources, and important business rules. Generated docs make lineage and contracts easier for consumers to explore.

02 / Example workflow

Validate before production promotion.

# Local development
 dbt build --select stg_orders+ 

# Generate project documentation
 dbt docs generate
Deployment pattern: run targeted checks in development or CI, review the change, then promote to a production job with explicit target credentials and alerting. Adapt commands to the installed dbt version and CI policy.

03 / Practice

Interview checks.

What would you include in a dbt deployment process?

Version-controlled code, automated parsing and tests, environment-specific targets, approval gates where required, production scheduling, observability, and a rollback or recovery plan.

Why generate and retain run artifacts?

Artifacts describe the project graph and run results. They support debugging, lineage, operational reporting, and state-aware build strategies.

How do you improve data discoverability?

Add model and column descriptions, document source contracts and metrics, run docs generation, and make the resulting lineage accessible to downstream users.
