02 / Core notes

Reason about rows and results.

Think in sets

SQL operates on relations. Define the intended row grain before joining or aggregating to avoid accidental duplication.

NULL is unknown

Use IS NULL or IS NOT NULL. Comparisons with NULL do not behave like ordinary true or false comparisons.

Window functions

Window functions calculate across related rows while preserving row-level output. Choose a deterministic ORDER BY when selecting one record.

Execution order

Know how FROM, WHERE, GROUP BY, HAVING, SELECT, window evaluation, and final ordering relate when diagnosing query behavior.

03 / Interview practice

Questions and answer frameworks.

How would you keep the latest row for each customer?

Use ROW_NUMBER partitioned by customer and ordered by an update timestamp descending, with a stable tie-breaker. Filter to row number 1 in a subquery or with QUALIFY where supported.

What is the difference between WHERE and HAVING?

WHERE filters input rows before grouping. HAVING filters grouped results after aggregation.

How can a join unexpectedly multiply rows?

The join keys may not be unique on one or both sides, or the chosen grain may be wrong. Check key cardinality, aggregate or deduplicate intentionally, and validate row counts before and after joins.

How do you tune a slow query?

Inspect the execution plan and workload evidence, then check scans, join strategy, filters, cardinality estimates, and returned columns. Make one targeted change and compare runtime and resource usage.
