Joins and data modeling

Understand row grain, join cardinality, and the reasons a query can duplicate or drop records.

Join behaviorExamplesPractice

01 / Join behavior

Know the grain on both sides.

INNER JOIN

Returns matching rows. Rows without a match on either side are excluded.

LEFT JOIN

Preserves all left-side rows and returns matching right-side data when available. Right-side filters in WHERE can unintentionally remove unmatched rows.

Cardinality

A one-to-many relationship multiplies matching rows. Check uniqueness and row counts before aggregating joined data.

Data grain

State what one row represents in each table. Join on keys that reflect that grain; avoid joining facts only by a non-unique descriptive attribute.

02 / Examples

Find unmatched records without multiplying rows.

SELECT c.customer_id
FROM customers c
WHERE NOT EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.customer_id = c.customer_id
);

Before joining two facts, aggregate each to the shared grain when the report needs one row per customer:

WITH customer_orders AS (
  SELECT customer_id, SUM(order_total) AS total_sales
  FROM orders
  GROUP BY customer_id
)
SELECT c.customer_id, o.total_sales
FROM customers c
LEFT JOIN customer_orders o
  ON o.customer_id = c.customer_id;

03 / Practice

Interview checks.

A join doubled your total. What do you inspect?

Check the grain and uniqueness of both join keys. Measure rows per key, identify many-to-many matches, and aggregate or deduplicate only when it matches the intended business definition.

How can a WHERE condition turn a LEFT JOIN into an effective INNER JOIN?

A WHERE predicate on the right-side table filters out NULL-extended unmatched rows. Put a match condition in ON when unmatched left rows should remain, or explicitly allow nulls where appropriate.

When is NOT EXISTS preferable to NOT IN?

NOT EXISTS expresses an anti-join and avoids the NULL behavior that can make NOT IN return unexpected results if the subquery contains NULL. Check optimizer behavior and indexes for the target database.
