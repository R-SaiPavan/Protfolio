SQL roadmap / 03

Aggregation and window functions

Summarize at the correct grain, then use window functions for rankings, running totals, and row-level comparisons.

ConceptsExamplesPractice

01 / Concepts

Group rows or analyze across rows.

GROUP BY

Collapses input rows into groups and returns aggregate results at the chosen grouping grain.

HAVING

Filters grouped results after aggregate values are computed; WHERE filters rows before grouping.

Window functions

Calculate over a partition while preserving individual rows. PARTITION BY defines groups; ORDER BY defines sequence.

Ranking functions

ROW_NUMBER assigns unique row positions; RANK and DENSE_RANK treat ties differently. Add a stable tie-breaker for deterministic selection.

02 / Examples

Rank within each customer.

WITH ranked_orders AS (
  SELECT customer_id, order_id, order_date,
         ROW_NUMBER() OVER (
           PARTITION BY customer_id
           ORDER BY order_date DESC, order_id DESC
         ) AS row_num
  FROM orders
)
SELECT customer_id, order_id, order_date
FROM ranked_orders
WHERE row_num = 1;

A running total uses an explicit window frame for predictable results:

SUM(order_total) OVER (
  PARTITION BY customer_id
  ORDER BY order_date, order_id
  ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
) AS running_total

03 / Practice

Interview checks.

What is the difference between ROW_NUMBER, RANK, and DENSE_RANK?

ROW_NUMBER assigns a unique number to each row. RANK gives ties the same rank and leaves gaps; DENSE_RANK gives ties the same rank without gaps.

Why use an explicit window frame?

It defines which rows contribute to a window calculation and avoids relying on dialect-specific defaults, especially for running aggregates with duplicate order values.

When would you use HAVING rather than WHERE?

Use WHERE to filter source rows before grouping. Use HAVING to filter groups based on aggregate results such as COUNT or SUM.
