Loading and transformation

Follow data from a staged file into a reliable curated table. Focus on validation, repeatable transformations, and safe recovery from failures.

Load flowSQL examplesPractice

01 / Load flow

Separate landing, validation, and serving.

1. Stage source files

Land files in cloud storage or an internal stage. Define a named file format for the actual file type, compression, and parsing rules.

2. Load to raw

Use COPY INTO or a suitable Snowpipe ingestion pattern. Capture load history, source file names, and ingestion timestamps for traceability.

3. Validate and transform

Check required keys, types, and row counts. Deduplicate source changes before applying incremental transformations.

4. Publish curated data

Use stable business keys and repeat-safe merge logic. Expose documented tables or views to downstream reporting.

02 / SQL examples

Load files and track changes.

Example COPY pattern. Replace stage, target, and file-format identifiers with names from your own environment.

COPY INTO raw.events
FROM @landing/events/
FILE_FORMAT = (FORMAT_NAME = 'json_format')
ON_ERROR = 'ABORT_STATEMENT';

A stream can expose table changes for downstream incremental processing:

CREATE STREAM raw.events_stream
  ON TABLE raw.events;
Retry safety: deduplicate each incoming batch deterministically before MERGE. Track which source files or batches were processed, and test a rerun after a partial failure.

03 / Practice

Interview checks.

How would you handle a malformed file without blocking every valid file?

Choose an error policy that matches the data contract, capture load errors, and route failed files or rows for investigation. Make the decision visible through metrics and alerts; do not silently discard invalid records.

How do you prevent duplicates when an ingestion task is retried?

Use stable keys, deterministic source deduplication, and idempotent target logic. Track input batches and test retry behavior after failures at different pipeline stages.

When would you use Snowpipe instead of scheduled COPY?

Consider Snowpipe for event-driven file ingestion with lower latency and less custom scheduling. A scheduled COPY can suit predictable batch windows. Compare freshness needs, expected volume, operational complexity, and cost.
