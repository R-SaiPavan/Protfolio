02 / Core notes

Concepts to explain clearly.

Three-layer architecture

Storage keeps compressed, columnar data; virtual warehouses provide independent compute; cloud services handle metadata, authentication, access control, and query coordination.

Micro-partitions and pruning

Snowflake automatically stores data in micro-partitions and tracks metadata. Filters can skip partitions that cannot match. Clustering keys can help selected large-table workloads, but reclustering has a cost.

Warehouses and concurrency

Use separate warehouses to isolate workloads. Resize to add resources for compute-heavy queries; use multi-cluster scaling when concurrency and queueing are the issue. Auto-suspend limits idle compute charges.

Incremental processing

Streams expose table changes and tasks run scheduled or chained SQL. Make processing repeat-safe with deterministic source deduplication, stable keys, and idempotent MERGE logic.

Query Profile

Use the operator graph to inspect scan volume, partitions scanned, join behavior, queue time, and spilling. Change the evidenced bottleneck, then compare runtime and credits.

Time Travel and Fail-safe

Time Travel supports querying or restoring historical data during the configured retention period. Fail-safe is a separate recovery period managed by Snowflake, not a routine self-service query feature.

03 / Interview practice

Questions and answer frameworks.

Use these as a starting point. For experience questions, connect the concepts to work you personally performed.

Explain Snowflake's architecture. How does it support independent scaling?

Snowflake separates storage, compute, and cloud services. Data is stored centrally, while virtual warehouses provide independent compute. This lets teams isolate workloads or scale compute without copying the underlying data. Cloud services coordinate metadata, security, and query execution.

When would you resize a warehouse versus use a multi-cluster warehouse?

Resize when a query or workload needs more compute resources. Use multi-cluster scaling when concurrent queries are queuing and the goal is more concurrent capacity. In both cases, compare the latency improvement with the credit impact and tune auto-suspend for idle time.

What are micro-partitions, and how do you improve pruning?

Micro-partitions are Snowflake-managed storage units with metadata such as value ranges. The optimizer uses that metadata to skip irrelevant partitions. Use selective predicates with compatible data types and avoid unnecessary transformations on filter columns. Consider a clustering key only when query profiles and workload measurements justify its maintenance cost.

How would you design an incremental ingestion pipeline?

Land source files in cloud storage, define a stage and file format, then load with COPY or an appropriate Snowpipe pattern. Validate and track inputs, transform incrementally with deterministic keys, and use streams and tasks where they fit. Add data-quality checks, observability, and a replay strategy so retries do not create duplicates.

A query became slow. What do you inspect first?

Compare query history and Query Profile with a known-good run. Check queue time, partitions scanned, bytes read, join growth, spilling, warehouse load, and data-volume changes. Optimize the identified scan, join, or concurrency bottleneck before simply increasing warehouse size.

How do you control Snowflake credit consumption?

Start with warehouse metering and query history. Right-size warehouses, enable auto-suspend and auto-resume, separate workloads when useful, reduce unnecessary scans, and set resource monitors or alerts. Verify that cost changes still meet freshness, concurrency, and latency targets.

How do you make a MERGE pipeline safe to retry?

Deduplicate the incoming batch by its match key using a deterministic tie-breaker. Use stable keys and explicit matched and unmatched logic. Prevent overlapping runs when necessary, track source batches, and test retries after partial failure to confirm the target remains consistent.

How do RBAC and masking policies work together?

Privileges are granted to roles, which can inherit privileges from other roles and be assigned to users. A masking policy changes how sensitive column values are displayed by role or context; a row access policy filters visible rows. Apply least privilege and test access using the roles that consumers actually assume.
