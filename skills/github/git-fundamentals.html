Git fundamentals

Understand the local Git model, commits, remotes, and how to inspect or recover changes safely.

Core modelCommand examplesPractice

01 / Core model

Track snapshots, not file diffs alone.

Working tree

The checked-out files you edit locally. Use status and diff to see what changed.

Staging index

The proposed content for the next commit. Stage only the changes you intend to record together.

Commit history

A commit records a snapshot and parent reference. Small, focused commits help review, bisect, and revert work.

Remote tracking

Remotes identify shared repositories. Fetch updates remote-tracking references without changing the current branch.

02 / Command examples

Inspect, stage, and record.

git status
  git diff
  git add path/to/file
  git diff --staged
  git commit -m "Describe the change"
  git log --oneline --decorate -10
Recovery: use git restore for unstaged file changes and git revert to create a new commit that reverses a shared change. Check status before destructive operations.

03 / Practice

Interview checks.

What is the difference between the working tree, index, and repository?

The working tree is the checked-out files, the index stages the next snapshot, and the repository stores commits and history.

What does git fetch do?

It downloads remote objects and updates remote-tracking references without merging those changes into the current branch.

How would you undo a commit already shared with a team?

Prefer git revert, which adds a new commit that reverses the change without rewriting shared history. Coordinate before rewriting published commits.
